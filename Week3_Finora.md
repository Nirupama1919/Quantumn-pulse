# Week 3 – Cognitive Load Triggers & Micro-Interactions

**Project:** Finora – Enterprise Financial Dashboard  
**Column 1:** HCI Research & Architecture  
**Column 2:** UI Design & Motion Prototyping (Figma, ProtoPie)

## Objective

Plan how the Finora dashboard should communicate important financial alerts and define a clear visual transition from the Normal State to the High-Alert State.

## Column 1 – HCI Research & Architecture: Cognitive Load Triggers

### Task focus

Define precise alert states and map how the interface shifts the user's attention during a market crash or an unusual financial event.

### Proposed alert-state structure

1. **Normal State:** The dashboard displays its regular financial information, including KPI cards, charts, filters, and transaction data.
2. **High-Alert State:** A prominent alert message is shown when a critical market event or anomaly is detected. The alert should clearly explain what happened and direct attention to the relevant information.
3. **Focus change:** Less important background content is visually de-emphasized so the alert is easier to notice.
4. **Return to normal:** After the alert is acknowledged or dismissed, the dashboard returns to its regular visual state.

### Design considerations

- Use clear and direct alert wording.
- Make the alert visually distinct from normal dashboard content.
- Avoid unnecessary animation or excessive warning elements.
- Keep important financial information understandable.
- Do not rely on colour alone; include a text label or icon with the alert.

## Column 2 – UI Design & Motion Prototyping: Micro-Interactions

### Task focus

Use ProtoPie or After Effects to animate the transition between the **Normal State** and **High-Alert State**, including dimming the background during a critical alert.

### Planned design work

1. Prepare the Normal State dashboard screen in Figma.
2. Create a High-Alert State version with a clear warning panel.
3. Add a dimmed overlay behind the alert while keeping the alert readable.
4. Prototype the transition from Normal State to High-Alert State.
5. Add an interaction to acknowledge or dismiss the alert and return to the Normal State.
6. Review the transition for clarity, timing, and readability.

### Suggested interaction sequence

- **Trigger:** A critical alert is activated.
- **Transition:** The dashboard background gradually dims.
- **Alert display:** The High-Alert message appears prominently.
- **User action:** The user acknowledges or dismisses the alert.
- **Return:** The overlay is removed and the dashboard returns to the Normal State.

## Expected Deliverables

- Normal State dashboard screen.
- High-Alert State dashboard screen.
- A prototype demonstrating the transition between both states.
- A short review of alert visibility and interaction clarity.
